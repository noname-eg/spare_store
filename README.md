# No Name

متجر إلكتروني للألبسة، مبني كتطبيق ويب كامل (Full-stack) بواجهة عربية/إنجليزية واتجاه دعم RTL.

المشروع قايم على نمط单体: واجهة React SPA وخادم Express يشتغلوا من نفس البورت، وقاعدة البيانات على Supabase، والنشر على Hostinger مربوط مباشرة بمستودع GitHub.

## المميزات

### واجهة المتجر

- تصفح المنتجات مع فلترة وترتيب حسب الفئة والسعر.
- صفحة منتج تعرض الصور، الألوان، والمقاسات المتاحة.
- سلة مشتريات محفوظة في `localStorage` وصفحة إتمام الطلب.
- كوبونات خصم مُدارة من لوحة التحكم.
- صفحة تأكيد الطلب (`order-summary/:id`).
- صفحات معلومات: `shipping` و`contact` بمحتوى قابل للتحرير من الإدارة.
- واجهة ثنائية اللغة (عربي/إنجليزي) مع تبديل اتجاه الصفحة تلقائيًا.
- تصميم متجاوب بالكامل على الموبايل والتابلت والديسكتوب.

### لوحة التحكم `/admin`

- تسجيل دخول محمي بكلمة مرور مُجزّأة بخوارزمية `scraping-resistant` hash.
- إدارة المنتجات (إضافة، تعديل، حذف، رفع الصور) ومتغيرات المنتج (اللون/المقاس/الكمية).
- إدارة الطلبات ومراجعتها وتحديث حالتها.
- إدارة الكوبونات.
- إدارة صفحات السياسات والمعلومات (Returns / Terms / Privacy / FAQ / Shipping / Contact).
- سجل تدقيق (Audit Log) لكل عملية إدارية.
- إعادة تعيين كلمة مرور الأدمن عبر script مستقل.

### SEO

- وسم `<head>` مخصص لكل مسار يُخدَّم من الخادم (Server-side injection).
- `sitemap.xml` يُولَّد تلقائيًا من المنتجات والصفحات المنشورة.
- بيانات منظّمة JSON-LD (Organization / WebSite / Product / BreadcrumbList).
- `hreflang` بديل بين النسختين العربية والإنجليزية.
- `robots.txt` و OG / Twitter meta tags.

### الأمان

- مفتاح `service_role` محصور في الخادم ولا يصل للمتصفح أبدًا.
- جلسات الأدمن عبر `HttpOnly` cookies مع توكنات مجزّأة مخزّنة في قاعدة البيانات.
- حد للطلبات (Rate limiting) على المسارات الحساسة.
- سياسات RLS على Supabase لجداول المتجر والصور.
- التحقق من كل المدخلات عبر Zod على حدود الـAPI.
- إنشاء الطلب يتم داخل معاملة Supabase ذرّية (`create_order`) لمنع الازدواج وتضارب المخزون.

## التقنيات المستخدمة

### الواجهة (Client)

| التقنية | الاستخدام |
|---|---|
| React 18 | بناء الواجهة بمكونات دوالية |
| React Router 6 | التنقل بين الصفحات (SPA) |
| TypeScript | أنواع صارمة في كل المشروع |
| Vite | أدوات البناء وبيئة التطوير |
| TailwindCSS 3 | التنسيق/themes من `client/global.css` |
| Radix UI + Lucide React | مكتبة مكونات UI والأيقونات |
| React Query | جلب بيانات الـAPI وإدارة الـcache |
| React Hook Form + Zod | النماذج والتحقق من المدخلات |

### الخادم (Server)

| التقنية | الاستخدام |
|---|---|
| Express 5 | REST API على `/api/*` |
| Zod | التحقق من صحة الطلبات |
| @supabase/supabase-js | الاتصال بقاعدة البيانات والتخزين |

### أدوات المشروع

- **PNPM 10** لإدارة الحزم.
- **Vitest** للاختبارات.
- **Prettier** للتنسيق (`pnpm format.fix`).

## التشغيل محليًا

### المتطلبات

- **Node.js 22**
- **pnpm 10**
- مشروع Supabase مفعّل مع credentials النتيجة

### الخطوات

```bash
# 1) تثبيت الحزم
pnpm install

# 2) تجهيز متغيرات البيئة
cp .env.example .env
# ثم عدّل القيم داخل .env

# 3) تشغيل بيئة التطوير (الواجهة + الخادم على نفس البورت)
pnpm dev
```

بعدها افتح `http://localhost:8080`.

---

## متغيرات البيئة

انسخ `.env.example` إلى `.env` ثم املأ القيم. ملف `.env` مستبعد من Git ولا يُرفع للمستودع.

| المتغير | الوصف | مطلوب |
|---|---|---|
| `SUPABASE_URL` | رابط مشروع Supabase | نعم |
| `SUPABASE_SERVICE_ROLE_KEY` | مفتاح `service_role` من Supabase | نعم |
| `APP_ORIGIN` | أصل الطلبات المسموح بها (CORS) | نعم |
| `NODE_ENV` | بيئة التشغيل (`development` / `production`) | لا |
| `PORT` | بورت الخادم (الافتراضي `3000`) | لا |

> **مهم:** `SUPABASE_SERVICE_ROLE_KEY` لا يُوضع أبدًا في متغيرات `VITE_*` ولا يصل إلى حزمة المتصفح. الخادم يرفض الإقلاع بدونه بدل التحوّل لمفتاح `anon` تلقائيًا.

## النشر

المشروع يُنشر على **Hostinger Node App**، والمستودع مربوط مباشرة بـ GitHub، فأي push على الفرع الرئيسيзывает بناءً ونشرًا تلقائيًا.

- إعدادات البناء: `builder.config.json`
  - `buildCommand`: `pnpm run build`
  - `buildOutputDir`: `dist/spa`
  - `nodeVersion`: `22`
- نقطة تشغيل الإنتاج: `dist/server/node-build.mjs`
- متغيرات البيئة تُضبط من لوحة Hostinger (وليس من المستودع).

التفاصيل الكاملة في [`DEPLOYMENT.md`](./DEPLOYMENT.md)، وخطة الإطلاق في [`PRODUCTION_PLAN.md`](./PRODUCTION_PLAN.md).

## الأمان

- لا تُرفع الأسرار إلى المستودع أبدًا، ولا تُكتب في ملفات أو تعليقات.
- أي تعديل في `supabase/migrations/` يجب أن يبقى متوافقًا مع نسخة منفذ.
- قبل الدمج، تأكد من نجاح `pnpm typecheck` و`pnpm test` و`pnpm build`.
